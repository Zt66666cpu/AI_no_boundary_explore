# 文本侧（C）工作区

> 维护：文本侧（C）｜更新：2026-10-20
> 官方要求：技术报告中文正文 3000–5000 字，按模板五部分；现场答辩占总分 40%。
>
> **名词约定**：本文及 `report/` 下所有文件中的 A / B / C 指**队内角色**（A 主程、B LLM 层、C 文本），与官方赛道的 A / B / C 编号无关——本文只讨论赛道 B「无界探索」。

## 文件说明

| 文件 | 用途 | 使用时机 |
|---|---|---|
| `技术侧对接清单.md` | 向 A / B 要什么、用什么格式 | 现在 |
| `实验日志.md` | 每次运行登记与分组汇总 | 每次实验当天 |
| `技术报告骨架.md` | 报告结构、字数预算、图表清单 | 有第一批数据后 |
| `提交清单.md` | 交件前逐项核对 | 11-19 前后 |
| `答辩提纲.md` | 讲稿结构、题库、演示预案 | 11-20 后集中准备 |

## 数据从哪里取

每次运行目录 `runs/world-*/evidence/N/`：

- `outcome.json`：分数、步数、终止原因
- `budget.json`：tokens、调用次数、时限
- `review.html`：汇总视图
- `steps.jsonl`：逐步动作与确认事件
- `replay.mp4`：录屏

报告里的数字只从这些文件取，不从聊天记录里抄。

## 写作口径

- 正文 3000–5000 字，不含封面、目录、参考文献、附录
- 五部分：我做了什么 / 我怎么实现 / 现在效果怎样 / 可选研究亮点 / 引用与团队分工
- 每个结论后面要么有数据，要么有可复查的运行路径
- 失败案例与成功案例同等重要，失败要写“现象—原因—改法—结果”

## 更新规则

- 实验当天登记，不攒到最后
- 报告里的数字必须与 `实验日志.md` 一致
- 提交前由 A / B 各核对一遍技术描述，C 核对格式、字数与引用
