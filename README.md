## 如何结合 Agent 使用资料库

核心原则：**不要整库乱读**，先喂给 Agent 三份"权威底稿"，再用资料库当检索源。

### 0. 开场把底稿喂给 Agent（每次新会话都做）

让 Agent 依次读这三份文件，建立规则上下文：

1. [`比赛资料库/02_比赛信息整理/AI无界杯_比赛信息.md`](比赛资料库/02_比赛信息整理/AI无界杯_比赛信息.md) — 全局速览
2. [`比赛资料库/02_比赛信息整理/官方资料存档/赛道B_无界探索_官方题面.md`](比赛资料库/02_比赛信息整理/官方资料存档/赛道B_无界探索_官方题面.md) — **权威规则**
3. [`比赛资料库/02_比赛信息整理/官方资料存档/下载/无界探索_智能体测评计分规则.txt`](比赛资料库/02_比赛信息整理/官方资料存档/下载/无界探索_智能体测评计分规则.txt) — 计分公式

> **可直接粘贴的开场提示词**
>
> ```
> 你是我的无界杯赛道 B（MineDojo 开放世界智能体）备赛助手。
> 先读这三个文件并复述关键约束：
>   1) 比赛资料库/02_比赛信息整理/AI无界杯_比赛信息.md
>   2) 比赛资料库/02_比赛信息整理/官方资料存档/赛道B_无界探索_官方题面.md
>   3) 比赛资料库/02_比赛信息整理/官方资料存档/下载/无界探索_智能体测评计分规则.txt
> 之后所有建议必须与官方题面一致；资料之间若有冲突，以官方题面为准并明确指出。
> 只引用 比赛资料库/ 里的内容，不要凭记忆或联网编造赛事规则；每个结论后面标出来源文件路径。
> ```

### 1. 查规则 / 查群内答疑 —— 当"赛务检索器"

| 想查什么 | 让 Agent 去哪读 |
|---|---|
| 赛制、日期、提交材料 | `02_比赛信息整理/AI无界杯_比赛信息.md` |
| 计分公式、科技树分值、作弊红线 | `官方资料存档/下载/无界探索_智能体测评计分规则.txt` |
| 学习路线、视频/论文清单 | `官方资料存档/赛道B_飞书学习指导.md` |
| "群里有人问过 X 吗" | `01_群消息原始/*/msg.jsonl`（JSONL，字段：`chat/发言人/时间/正文/类型`） |
| 关键字命中清单 | `02_比赛信息整理/比赛相关消息.md`（122 条） |

> "从 `01_群消息原始/` 里找出所有提到 **Docker / 开发包 / 算力 / 组队** 的消息，按时间列出，并标出是哪条文件路径。"

### 2. 搭环境 —— 让 Agent 直接干活

开发包原件在 [`官方资料存档/下载/赛道B_智能体开发包.zip`](比赛资料库/02_比赛信息整理/官方资料存档/下载/赛道B_智能体开发包.zip)，内含 `agent.py` / `model_agent.py` / `model_api.py` / `minecraft_actions.py` / `practice.py` / `evaluation_adapters/` 等。

> WSL2 里跑通官方示例的提示词：
> ```
> 在 WSL2+Ubuntu 里帮我搭 MineDojo 环境：
> 1) 先解压 比赛资料库/02_比赛信息整理/官方资料存档/下载/赛道B_智能体开发包.zip，说明每个文件的作用；
> 2) 按官网 Docker 教程（比赛资料库/02_比赛信息整理/官方资料存档/赛道B_无界探索_官方题面.md 第六节附链接）一步步来；
> 3) 每步先告诉我你要执行什么命令、风险是什么，等我确认再执行。
> ```

### 3. 定策略 —— 用计分公式让 Agent 做取舍

> "把 `无界探索_智能体测评计分规则.txt` 里的计分公式提取出来，输出一张表：里程碑 → 分值 → 前置依赖 → 建议获取顺序；再按 效率分权重（木 8 / 石 12 / 铁 20）分析'先追木镐还是先屯资源'的收益差。"

### 4. 写技术报告 —— 让 Agent 搭骨架

> "依据 `官方资料存档/下载/技术报告模板.docx` 与评审四项（方案设计 / 工程实现 / 实验分析 / 技术表达），生成 3000–5000 字报告大纲，留出实验数据占位；不要编造实验结果。"

### 5. 给 Agent 的固定约束（建议写进 Agent 配置）

- 只引用 `比赛资料库/` 内的内容，禁止臆造赛事规则
- 每个结论标注来源文件路径
- 改代码前先说明"动哪个文件、为什么、影响面"
- 涉及提交材料时，复核是否满足"代码 ZIP + 技术报告 PDF"两项必交

## 协作约定

1. `比赛资料库/` 为**只读参考区**：新增资料请放入对应子目录，不要覆盖既有文件。
2. 大文件（如 `LLM.pdf` 约 80 MB）已直接入库；后续若再加二进制大文件，建议改用 Git LFS。
3. 讨论得出的结论请沉淀回 `02_比赛信息整理/`，不要只留在聊天记录里。
4. 代码请写在根目录新建的 `src/` 等目录，与资料库分离。
